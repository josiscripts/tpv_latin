## Key Fixes Implemented

### 1. **Claude Extended Thinking Block Handling** ✅
**Problem**: Claude returns responses with thinking blocks before text blocks:
```json
[{"type":"thinking"}, {"type":"text"}]
```

**Solution**: Changed response handler to find 'text' block instead of assuming position:
```typescript
const textBlock = (response.content as Array<any>).find((c: any) => c.type === 'text');
```

**Impact**: Eliminates HTTP 500 errors and allows successful document processing.

**File**: `supabase/functions/process-document/index.ts` (lines 691-702)

---

### 2. **RPC Function Row Count Handling** ✅
**Problem**: RPC functions using `RETURNING TRUE INTO v_integer_var;` caused SQL type errors.

**Fixed Functions**:
- `finalize_document_as_processed()` - Line 78 bug
- `claim_document_for_processing()` - Line 45 bug  
- `mark_document_as_error()` - Similar pattern

**Solution**: Use `IF FOUND` or `GET DIAGNOSTICS v_var = ROW_COUNT;` instead of buggy RETURNING pattern.

**Impact**: RPC functions now execute successfully without type errors.

## Lessons Learned

### Issue: Lease Expiration & Recovery
- Documents stuck in 'processing' status with expired leases prevented reprocessing
- RPC WHERE clause requires status IN ('uploaded', 'error'), not 'processing'
- Workaround: Manually reset document back to 'uploaded' when lease expires
- Future: Implement automatic recovery via scheduled job or API endpoint

### Issue: RPC Pattern Anti-pattern
- PostgreSQL pattern `RETURNING TRUE INTO integer_var` is incorrect
- Must use `IF FOUND` or `GET DIAGNOSTICS ... ROW_COUNT`
- This pattern appears in multiple RPC functions - fixed all instances

### Issue: Claude Model Variations
- Extended thinking adds content blocks to responses
- Response structure varies based on model features
- Solution: Always search for 'text' block, don't assume position
